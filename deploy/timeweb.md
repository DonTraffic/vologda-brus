# Развёртывание в Timeweb Cloud

Сайт собирается из GitHub (`DonTraffic/vologda-brus`, ветка `main`).

**С 28 октября 2026 приложение серверное, а не статическое.** Это сделано ради
приёма заявок: письмо нельзя отправить из браузера, SMTP ему недоступен, а у
статики нет исполняемого кода. Нужен живой процесс, который примет форму и
передаст письмо на `smtp.timeweb.ru`.

Страницы при этом остались предсобранными: `nitro.prerender` готовит их на
сборке, и сервер отдаёт готовый HTML, а не собирает его на каждый заход.
Скорость от переезда на сервер не пострадала.

---

## Что задать в панели

| Поле | Значение |
|---|---|
| Тип приложения | **Backend**, Node.js (не Frontend) |
| Команда сборки | `npm run build` |
| Команда запуска | `npm start` |
| Порт | берётся из переменной `PORT`, её выставляет сама площадка |

Команда сборки и раньше, и теперь устойчива к ошибке: `npm run build` и
`npm run generate` дают согласованный результат, шаги после сборки висят на
`postbuild`/`postgenerate` и пропустить их нельзя.

## Переменные окружения

Задаются в панели приложения. В репозиторий они не попадают, образец — в
`.env.example`.

### Приём заявок

| Переменная | Что это |
|---|---|
| `NUXT_SMTP_HOST` | `smtp.timeweb.ru` |
| `NUXT_SMTP_PORT` | `465` (неявный TLS) или `587` (STARTTLS) |
| `NUXT_SMTP_USER` | полный адрес ящика — он же отправитель |
| `NUXT_SMTP_PASS` | пароль ящика |
| `NUXT_MAIL_TO` | куда складывать заявки; пусто — на свой же ящик |

Ящик создаётся в разделе «Почта» панели Timeweb. **Отправитель обязан совпадать
с логином**: Timeweb не даёт отправлять от чужого адреса.

Пока `NUXT_SMTP_USER` или `NUXT_SMTP_PASS` пустые, маршрут `/api/lead` отвечает
кодом 503, а форма честно пишет «приём заявок пока не настроен» и предлагает
позвонить. Молча терять заявки она не будет ни при какой настройке.

### Аналитика

| Переменная | Что это |
|---|---|
| `NUXT_PUBLIC_METRIKA_ID` | номер счётчика Метрики, только цифры |
| `NUXT_PUBLIC_GA_ID` | поток GA4 вида `G-XXXXXXXXXX` |
| `NUXT_PUBLIC_YANDEX_VERIFICATION` | подтверждение Вебмастера |
| `NUXT_PUBLIC_GOOGLE_VERIFICATION` | подтверждение Search Console |

Счётчик Метрики нужен **новый**: `107226117` собирал данные другого сайта, а у
переносимого `вологдабрус.рф` аналитики не было вовсе.

Google Analytics для российского заказчика лучше не включать вовсе: он пишет
данные посетителей на серверы Google — та же статья 152-ФЗ, из-за которой мы
отказались от внешних приёмников форм. Переменную просто не задавайте.

## Что переход на сервер закрыл сам собой

**Страница 404.** Раньше на любом несуществующем адресе хостинг отдавал копию
главной с кодом 200 — переключатель «SPA Fallback». Теперь несуществующие
адреса обрабатывает сам Nuxt и отвечает настоящим кодом 404. Переключатель у
бэкенд-приложения не нужен, скрипт `fix-404.mjs` при серверной сборке сам себя
отключает.

**Карта сайта.** `sitemap.xml` стал серверным маршрутом
(`server/routes/sitemap.xml.get.ts`) и строится из данных блога. Раньше её
писал скрипт после сборки — и файл оказывался невидимым, потому что список
публичных файлов Nitro составляет на сборке. Выпасть из сборки карта больше
не может.

## Что проверить сразу после переключения

```
curl -I  https://vologda-brus.ru/                      # 200
curl -I  https://vologda-brus.ru/net-takoy-stranicy/   # должно стать 404, а не 200
curl -s  https://vologda-brus.ru/sitemap.xml | head    # 9 адресов
curl -s  https://vologda-brus.ru/robots.txt
```

Затем отправить по одной тестовой заявке с каждой формы — расчёт на главной,
консультация на главной, заявка на странице дилеров — и убедиться, что письма
пришли со всеми полями и не в спам.

Если письма не уходят, первое подозрение — закрытый исходящий порт 465 из
контейнера. Проверяется в логе приложения: там будет строка
`[lead] письмо не ушло:` с причиной. Лечится переключением на 587.

## Что осталось на панели

Набор переключателей у бэкенд-приложения может отличаться от фронтендового —
проверить после переключения типа.

* **Домены.** `www.vologda-brus.ru` в DNS уже указывает на приложение, но не
  привязан, поэтому там ошибка сертификата. Привязать и поставить редирект на
  основной адрес. `вологдабрус.рф` до сих пор отдаёт старый сайт на Тильде
  через DDoS-Guard — записи не переключены.
* **Сжатие.** Сейчас не включено: главная отдаётся как 66 КБ вместо примерно
  13. Это самая дешёвая правка на сайте — из-за неё LCP на телефоне 4,8 с
  вместо примерно 2,5.
* **Защитные заголовки.** HSTS, `X-Content-Type-Options`, `X-Frame-Options`,
  `Permissions-Policy`. Пятый, `Referrer-Policy`, уже задаётся мета-тегом
  страницы.

Сжатие и заголовки теперь можно задать и в коде — серверное приложение умеет
само выставлять заголовки ответа и отдавать сжатые файлы, без всякой панели.
Если площадка этого не предложит переключателем, скажите — сделаю в коде.

## Постраничный перенос со старого адреса

Адреса статей на Тильде имеют вид `/tpost/<хеш>-<название>`. Редиректы на этой
площадке работают только по точному совпадению пути, масок нет, поэтому пять
статей придётся перечислить вручную. С серверным приложением появился и второй
путь — прописать соответствие прямо в коде, одним правилом с разбором пути.
