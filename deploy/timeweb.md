# Настройки App Platform в Timeweb Cloud

Сайт собирается из GitHub (`DonTraffic/vologda-brus`, ветка `main`) и раздаётся
App Platform как статика. **Своего конфига веб-сервера на этом хостинге нет** —
загрузить Caddyfile или nginx.conf нельзя. Всё, что в обычной жизни пишется в
конфиг сервера, здесь задаётся переключателями в панели, и их набор ограничен.

Лежащий рядом `nginx.conf` к текущему хостингу **не применяется**. Он был
написан под отдельный сервер и остаётся на случай переезда.

Что настраивается в панели (по документации на 27 октября 2026):

| Возможность | Ограничение |
|---|---|
| Сжатие | `gzip`, `zstd`. Brotli нет |
| HTTP-заголовки | **не больше 10 правил**, применяются ко всему приложению — привязать правило к пути нельзя |
| Редиректы | **не больше 10**, только точное совпадение пути или редирект по домену. Маски и регулярные выражения не поддерживаются |
| SPA Fallback | переключатель: отдавать `/index.html` с кодом 200 или `/404.html` с кодом 404 |
| Домены и сертификаты | при привязке домена сертификат Let's Encrypt выпускается и продлевается автоматически |

---

## Что сделать, по порядку важности

### 1. Выключить SPA Fallback

**Настройки приложения → SPA Fallback → выключить.**

Сейчас он включён, и поэтому любой несуществующий адрес отдаёт копию главной
с кодом 200: поисковик видит бесконечное число одинаковых страниц, а человек
по битой ссылке не понимает, что ошибся адресом.

Выключать безопасно: все страницы сайта собраны заранее отдельными файлами,
подмена главной им не нужна ни для одного адреса.

После выключения хостинг станет отдавать `/404.html` с кодом 404. Сборка
кладёт туда настоящую страницу с заголовком «Этот брус куда-то делся» — это
делает `scripts/fix-404.mjs` — он выполняется при любой команде сборки,
см. раздел «Команда сборки».

### 2. Включить сжатие

**Настройки приложения → сжатие → отметить `gzip` и `zstd`.**

Сейчас не сжимается ничего: ни один из 40 ответов на главной не имеет
`Content-Encoding`. Главная отдаётся как 66 КБ вместо 12,7 КБ, текстовых
файлов на странице 416 КБ против 135 КБ под gzip. Это самая дешёвая правка на
сайте — две галочки убирают две трети текстового трафика.

### 3. Привязать домен `www.vologda-brus.ru` и поставить редирект

**Настройки → домены → добавить `www.vologda-brus.ru`**, затем
**редиректы → тип «host» → с `www.vologda-brus.ru` на `vologda-brus.ru`, код 301.**

Сейчас сертификат выпущен только на `vologda-brus.ru`, и на адресе с `www`
браузер показывает полноэкранное предупреждение «Подключение не защищено».
DNS у `www` уже указывает на приложение, так что сертификат выпустится сам
сразу после привязки.

### 4. Добавить защитные заголовки — 5 правил из 10

**Настройки → HTTP-заголовки**, все пять типа `set`:

| Имя | Значение |
|---|---|
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `X-Frame-Options` | `SAMEORIGIN` |
| `Permissions-Policy` | `geolocation=(), microphone=(), camera=()` |

Из этих пяти `Referrer-Policy` **с 28 октября задаётся самой страницей** —
`<meta name="referrer">` в `nuxt.config.ts`. Правило в панели всё равно лучше
(заголовок действует и на картинки, и на файлы, а не только на HTML), но если
правил не хватит, это то, которым можно пожертвовать.

Остальные четыре мета-тегом задать нельзя в принципе: `X-Frame-Options` и
`X-Content-Type-Options` браузеры из `<meta http-equiv>` не читают, HSTS тем
более. Они бывают только настоящими заголовками ответа.

Сейчас из пяти не отдаётся ни один.

### 5. Редирект со старого адреса страницы 404

**Редиректы → тип «path» → с `/error404` на `/404/`, код 301.** Одно правило.

Это адрес страницы «не найдено» со старого сайта на Тильде.

### 6. По желанию: редирект со старого адреса контактов

**Редиректы → тип «path» → с `/contacts` на `/`, код 301**, и то же самое
с `/contacts/`. Два правила: панель принимает только точное совпадение пути,
поэтому вариант со слешем и без слеша приходится заводить отдельно.

Зачем: страницу контактов 27 октября удалили — контакты и так стоят в подвале
на каждой странице, а отдельная страница дублировала их (телефон и адрес по
семь раз на одной странице, две карты сразу) и не была ни с чего слинкована.

Но на **прежнем** `vologda-brus.ru` (сборка Рег.ру, до 23 октября) страница
`/contacts` была: это зафиксировано в аудите от 3 октября — заголовок
«Контакты», причём открывались оба варианта адреса. Значит адрес мог попасть
в индекс, и без редиректа он отдаст 404.

На `вологдабрус.рф` (Тильда) такой страницы не было — там `/contacts` всегда
отдавал 404, это проверено. Так что если индексировался только Тильда-сайт,
правила можно не заводить и сэкономить два слота из десяти.

## Чего на этом хостинге сделать нельзя

**Кэширование статики — не полностью.** Правила заголовков применяются ко всему
приложению, а нужны разные: файлы в `/_nuxt/` и `/images/` можно держать в
браузере год (имена содержат хеш и меняются вместе с содержимым), а HTML —
только с обязательной проверкой. Одним общим правилом либо страницы зависнут
устаревшими на год, либо картинки и скрипты перестанут кэшироваться.

Сейчас заголовков кэширования нет вовсе, но `ETag` работает: повторный запрос
отдаёт 304 и ноль байт. То есть трафик не тратится, тратятся только обращения
к серверу — около семидесяти на переход.

**Что делать:** спросить поддержку Timeweb, можно ли привязать правило
заголовка к пути (в документации такой возможности нет, но она могла не
попасть в документацию). Если нельзя — оставить как есть: общее правило
сделает хуже, а не лучше. Пункт ТЗ «Запоминание страниц браузером» на этом
хостинге закрывается только частично, и это ограничение площадки, а не сборки.

**Постраничные переадресации со старых адресов Тильды** (`/tpost/<хеш>-<адрес>`
на `/blog/<адрес>`). Нужны маски, а панель принимает только точное совпадение
пути. Либо перечислять каждый адрес отдельным правилом из десяти доступных,
либо отказаться.

**Адреса без слеша на конце.** Веб-сервер App Platform отдаёт страницы из папок
и сам переадресует `/contacts` на `/contacts/` кодом 308 — поменять это нельзя.
Поэтому в коде всё приведено к виду **со** слешем: canonical, `og:url`, карта
сайта и внутренние ссылки. Если хостинг когда-нибудь изменит поведение, править
надо `useSeo.ts`, `scripts/sitemap.mjs` и ссылки в `app/data/site.ts`.

## Команда сборки

Папка с результатом — `.output/public`. Команда может быть любой из двух:

```
npm run generate
npm run build
```

**Перепутать больше нельзя — и это специально.** 28 октября выяснилось, что в
панели стояло `npm run build`, и из-за этого на сайте не было ни `sitemap.xml`,
ни настоящей страницы 404: сами страницы собирались (их всё равно пререндерит
`nitro.prerender`), а два шага после сборки не выполнялись. Картина выглядела
обманчиво — сайт работал «почти весь».

Чтобы команда в панели перестала иметь значение, сделано два изменения:

* в `nuxt.config.ts` стоит `nitro.preset: 'static'` — теперь `nuxt build`
  даёт ровно то же, что `nuxt generate`, то есть статику в `.output/public`,
  а не серверное приложение;
* шаги после сборки перенесены в `postbuild` и `postgenerate` в `package.json`.
  Это штатный механизм npm: он выполняет их сам после `npm run build` и после
  `npm run generate`, пропустить их нельзя.

Проверено сборкой из чистой копии (`rm -rf .output .nuxt && npm run build`):
`404.html` получается 17 390 Б вместо оболочки на 1 742 Б, `sitemap.xml` — на
9 адресов.

**Отдельно про карту сайта.** До 27 октября `scripts/sitemap.mjs` писал в папку
`dist` — а это символическая ссылка на `.output/public`, которая существует
только на машине разработчика: она в `.gitignore` и ведёт по абсолютному пути.
На сборке из GitHub такой папки нет, скрипт падал, и `sitemap.xml` не
создавался — именно поэтому на сайте его не было, хотя `robots.txt` на него
ссылается. Теперь оба скрипта берут `.output/public` напрямую; проверено
сборкой из чистой копии репозитория без папок `dist` и `.output`.

## Переменные окружения

Задаются в настройках приложения, подробности — в README, разделы «Аналитика»
и «Приём заявок»:

```
NUXT_PUBLIC_FORM_ENDPOINT        приёмник заявок — без него формы не работают
NUXT_PUBLIC_METRIKA_ID           номер нового счётчика Метрики
NUXT_PUBLIC_GA_ID                G-XXXXXXXXXX
NUXT_PUBLIC_YANDEX_VERIFICATION  подтверждение Яндекс.Вебмастера
NUXT_PUBLIC_GOOGLE_VERIFICATION  подтверждение Google Search Console
```

Значения вшиваются в статику на сборке, поэтому после их изменения приложение
надо пересобрать.
