# vologda-brus-site

Сайт «Вологда Брус» на Nuxt 4 — перенос оформления и содержания с текущего
сайта на Тильде (`вологдабрус.рф`) в собственный проект.

Перенесены вёрстка, тексты и фотографии. Код платформы Тильды не копировался:
компоненты, стили и скрипты написаны заново, поэтому попутно закрыты
технические проблемы из аудита (`../Работа по сайту/Аудит сайта вологдабрус.рф.md`).

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # серверное приложение в .output
npm start          # запустить собранное на http://localhost:3000
```

Нужен Node 20+ (проверено на 26).

## Аналитика

Счётчики подключаются **номерами в переменных окружения**, а не правкой кода.
Образец файла — `.env.example`, скопировать в `.env` и заполнить. Код подключения
живёт в `app/plugins/analytics.ts`, цели — в `app/composables/useAnalytics.ts`.

```bash
cp .env.example .env     # и заполнить
npm run build            # номера попадают в HTML на сборке
```

Пока номер пустой — счётчик не подключается вовсе: ни запроса, ни тега в
разметке. Поэтому сборку для проверки можно собирать без `.env`, статистика
боевого сайта от этого не пострадает.

### Что куда вставлять

| Переменная | Где взять | Что даёт |
|---|---|---|
| `NUXT_PUBLIC_METRIKA_ID` | metrika.yandex.ru → **создать счётчик** → Настройка → «Номер счётчика». Счётчик нужен новый: переносимый сайт вологдабрус.рф аналитики не имел, наследовать нечего. Счётчик `107226117` на этом домене собирал данные прежнего сайта на Рег.ру — другого сайта, заменённого 23.10.2026 | Посещаемость, источники, карта прокрутки и кликов, запись действий посетителей |
| `NUXT_PUBLIC_GA_ID` | analytics.google.com → Администратор → Потоки данных → поток → «Идентификатор потока данных», вида `G-XXXXXXXXXX` | То же по второму счётчику |
| `NUXT_PUBLIC_YANDEX_VERIFICATION` | webmaster.yandex.ru → добавить сайт → способ «Мета-тег» → значение `content="…"` | Доступ к отчётам Вебмастера, передача карты сайта |
| `NUXT_PUBLIC_GOOGLE_VERIFICATION` | search.google.com/search-console → ресурс «Префикс URL» → способ «Тег HTML» → значение `content="…"` | То же в Search Console |

В переменные подтверждения идёт **только содержимое `content`**, без обёртки
`<meta>`. Подтверждение файлом в корне тоже годится — файл кладётся в `public/`,
тогда переменная не нужна.

Параметры Метрики уже выставлены по ТЗ (этап 8): карта кликов, учёт переходов по
внешним ссылкам, точный учёт отказов, вебвизор. Отдельно включать в интерфейсе
ничего не нужно, кроме самого вебвизора в настройках счётчика.

### Цели

Семь целей отправляются в оба счётчика под одинаковыми именами. В интерфейсе
Метрики каждая создаётся как цель типа **«JavaScript-событие»** с
идентификатором из левого столбца:

| Идентификатор цели | Когда срабатывает |
|---|---|
| `form_calc` | Отправлена форма расчёта на главной — **только при успешном приёме заявки** |
| `form_consult` | Отправлена форма консультации (главная и страница дилеров) |
| `phone_click` | Клик по номеру телефона в любом месте сайта |
| `email_click` | Клик по адресу почты |
| `messenger_click` | Переход в Telegram, MAX или WhatsApp |
| `messenger_modal` | Открыто окно выбора мессенджера — кнопки-призывы и лид-магниты |
| `route_click` | Клик по ссылке на Яндекс.Карты (построение маршрута) |

Две тонкости, о которых легко забыть:

- **Цели на формы не сработают, пока не настроен приём заявок**
  (`NUXT_PUBLIC_FORM_ENDPOINT`): цель отправляется после успешного ответа
  приёмника, а не по нажатию кнопки. Так в статистику попадают заявки, а не
  попытки. Сначала приёмник — потом проверка целей.
- Срабатывание по скрытому полю-ловушке для роботов цель **не** отмечает,
  иначе статистика заявок наполнилась бы спамом.

Новую цель добавлять так: имя в `GOALS` (`app/composables/useAnalytics.ts`),
затем `reachGoal(GOALS.новаяЦель)` в нужном месте. Клики по ссылкам отдельной
разметки не требуют — их ловит один обработчик в плагине по адресу ссылки.

## Структура

```
app/
  assets/
    scss/           дизайн-система: токены, миксины, сброс, шрифты
    fonts/          Open Sans локально (4 подмножества, переменное начертание)
  components/
    ui/             базовые: BaseButton, SmartImage, SectionHeader,
                    GalleryGrid, BeforeAfter, FormField, RadioGroup, IconChat
                    (без префикса папки — см. nuxt.config)
    layout/         SiteHeader, SiteFooter, MessengerModal, CookieBanner
    sections/       блоки главной, по одному на секцию
  composables/
    useImage        srcset и пропорции из манифеста картинок
    useSeo          title, description, canonical, Open Graph
    useLeadForm     отправка заявки
    useMessengerModal
  data/
    site.ts         контакты, реквизиты, навигация, мессенджеры
    content.ts      тексты секций главной
    posts.ts        статьи блога
    policy.ts       текст политики конфиденциальности
    images.json     манифест: доступные ширины и реальные размеры
  pages/            index, blog, blog/[slug], contacts, dealers, privacy-policy
  error.vue         404
public/images/      пережатые картинки: WebP 640/1024/1600 + JPEG
server/api/           приём заявок: lead.post.ts
server/routes/        карта сайта: sitemap.xml.get.ts
server/utils/         отправка почты и ограничение частоты
_source/            разбор исходника Тильды (в репозиторий не идёт)
```

Содержание отделено от вёрстки: правка телефона, адреса или текста секции —
это правка `app/data/*`, а не обход компонентов.

## Что изменилось против версии на Тильде

| | Тильда | Здесь |
|---|---|---|
| HTML главной | 805 КБ (115 КБ сжатый) | 65 КБ (12,5 КБ сжатый) |
| CSS | 364 КБ встроено в каждую страницу | 49 КБ отдельными файлами, скачиваются один раз |
| JS | ~2 МБ, 24 файла | 352 КБ (карта — ещё 1 МБ, но только когда доедешь до неё) |
| Вес при загрузке | — | 0,99 МБ |
| Картинки при полной прокрутке | 22,5 МБ оригиналами | 5,0 МБ целиком со скриптами и шрифтами |
| Формат картинок | только JPEG/PNG | WebP + JPEG, 3 ширины, `srcset` |
| `<title>` главной | «Главная» | с запросом, регионом и брендом |
| `description` | нет ни на одной странице | на всех, включая пять статей |
| `<h1>` | нет ни одного на сайте | по одному на страницу |
| Кнопки-призывы | 15 штук через `javascript:` | настоящие ссылки |
| Шрифты | 3 блокирующих запроса к Google, Jura и Manrope не использовались | локально, только Open Sans |
| Микроразметка | 63 пустых `ImageObject` | `LocalBusiness` + `BlogPosting` |
| Список статей | рисуется скриптом, ссылок нет | обычные страницы в карте сайта |
| Защита форм | нет | honeypot + проверка полей |
| Страница дилеров | нет (а пункт меню есть) | `/dealers` |
| Страница контактов | нет | `/contacts` с картой и графиком |
| Реквизиты и карта | нет нигде | полоса над подвалом на всех страницах |

Сетка повторяет Тильду: до 1200 px колонка 940 (три карточки по 300 с шагом
20), шире — колонка 1160 (три по 360 с шагом 40). Миксины `t-container`
и `t-cols-3` в `app/assets/scss/_mixins.scss`.

Появление блоков при прокрутке перенесено вместе с параметрами оригинала
(`app/plugins/reveal.ts`, директива `v-reveal`): выезд слева и справа на
100 px за 0,5 с, проявление за 1 с, приближение с 0,9 — кривая
`cubic-bezier(.19,1,.22,1)`, цепочки с шагом 0,16 с. Отличие одно: прячущий
класс навешивает браузер, поэтому при выключенном JS страница показывает всё
сразу, а не остаётся пустой. При `prefers-reduced-motion` анимации выключены.

Ленты «Производство в Вологде» и снимков производства листаются мышью
(перетаскиванием), кнопками и сами по себе раз в 5 секунд — пауза при
наведении, фокусе и при `prefers-reduced-motion` (`app/composables/useCarousel.ts`).

Полоса с реквизитами и картой производства (`app/components/layout/ContactsMap.vue`)
стоит над подвалом на всех страницах. Карта — MapLibre GL на тайлах OpenFreeMap,
тёмный стиль; библиотека грузится только когда блок доезжает до экрана, а при
ошибке на её месте остаётся тёмная подложка и адрес текстом. Отдельный файл
воркера MapLibre кладёт в `public/vendor/` скрипт `scripts/copy-maplibre.mjs`
(он же вызывается из `npm run dev` и `npm run generate`).

Страницы блога, статьи, политика и 404 сверены со страницами Тильды по
координатам, кеглям и цветам: экран-обложка блога 700 px, лента в три колонки
по 300 px с шагом 20, колонка статьи 620 px, текст 18/25,2, плашка 404 с
нарисованным домом перенесена вместе с графикой.

Исправлены опечатки: «оффертой» → «офертой», «Выберете» → «Выберите»,
«клеёного» → «клееного», лишний пробел в «200 р/м ²», кавычки в
«Двойной брус», убрана заглушка «Tilda Publishing», год в подвале считается,
а не вписан.

Ответы заказчика от 12.10.2026 учтены: имя второго эксперта — «Алексей
Виноградов», реквизиты — ИП Виноградов Алексей Михайлович (ИНН 350701926897,
ОГРНИП 326350000007560), адрес производства — Московское шоссе, 44,
WhatsApp остаётся. Осталось:

1. **Кто оператор в политике конфиденциальности.** В тексте документа назван
   ИП Курочкин Юрий Николаевич (ИНН 772131133731) — не тот предприниматель, чьи
   реквизиты прислал заказчик. Подвал и микроразметка берут `LEGAL` из
   `app/data/site.ts`, политика — `POLICY_OPERATOR` из `app/data/policy.ts`.
   Переписывать юридический документ без ответа заказчика нельзя.
2. **Мобильный номер для WhatsApp.** Заказчик решил WhatsApp оставить, но
   в `MESSENGERS` подставлен городской `+7 499` — на нём WhatsApp не работает.
3. **График работы** — `WORK_HOURS` в `app/data/site.ts`. Указан
   предположительно; индекс и координаты производства определены по
   подтверждённому адресу.
4. **Сколько лет компания на рынке.** На сайте стоит «с 2017 года» (девять
   лет), а в статье блога — «мы на рынке больше 12 лет». В цифрах первого
   экрана оставлено «с 2017 на рынке», текст статьи не трогали: это слова
   компании. Нужен один год основания.
5. **Куда отправлять заявки.** Нужен ящик заказчика на российской почте —
   например, созданный в разделе «Почта» панели Timeweb. Приём заявок до
   этого выключен: `formEndpoint` в `nuxt.config.ts` пуст, и форма честно
   говорит, что приём не настроен.
4. **Фото экспертов в большем разрешении.** Оригиналы на Тильде всего
   372×560 и 533×800 — на экранах с высокой плотностью будут мягкими.
5. **Приёмник заявок — код готов, ждёт ящика.** Заявку принимает маршрут
   `/api/lead` и отправляет письмом через SMTP; данные при этом не покидают
   Россию. Осталось создать ящик в разделе «Почта» панели Timeweb и прописать
   `NUXT_SMTP_USER`, `NUXT_SMTP_PASS` и `NUXT_MAIL_TO`. Пока они пустые, форма
   честно пишет «приём заявок пока не настроен». Внешние службы приёма форм
   (FormSubmit и подобные) не рассматриваются: заявка легла бы первой записью
   на иностранный сервер, а ч. 5 ст. 18 152-ФЗ с 01.07.2025 это запрещает. По
   той же причине получателем не может быть gmail.
6. **Счётчик Метрики** — на обоих действующих сайтах аналитики нет вовсе.
   Поставить до запуска, чтобы остался замер «до».
7. **Решение по домену.** `SITE_URL` в `nuxt.config.ts` стоит
   `https://vologda-brus.ru`: от него считаются canonical, Open Graph,
   `robots.txt` и карта сайта. Если основным станет кириллический адрес —
   поменять в одном месте.

## Развёртывание

Сайт собирается из GitHub (`DonTraffic/vologda-brus`, ветка `main`) и работает
в **App Platform в Timeweb Cloud** как серверное приложение Node.js.

| Поле в панели | Значение |
|---|---|
| Тип приложения | Backend, Node.js |
| Команда сборки | `npm run build` |
| Команда запуска | `npm start` |

Серверным приложение стало 28 октября 2026 ради приёма заявок: письмо нельзя
отправить из браузера, SMTP ему недоступен, а у статики нет исполняемого кода.
Страницы при этом остались предсобранными — сервер отдаёт готовый HTML, а не
собирает его на каждый заход, поэтому скорость не пострадала.

Переход заодно закрыл две давние проблемы. Несуществующие адреса теперь
отвечают настоящим кодом 404, а не копией главной с кодом 200. И `sitemap.xml`
стал серверным маршрутом вместо файла, который дописывался после сборки и
из-за этого оказывался невидимым.

**Что ещё задать в панели — `deploy/timeweb.md`.** Коротко: привязать `www`,
включить сжатие, добавить четыре защитных заголовка.

Файл `deploy/nginx.conf` к текущему хостингу **не применяется** — он написан
под отдельный сервер и остаётся на случай переезда.

Переменные окружения задаются в настройках приложения. Номера счётчиков
вшиваются в HTML на сборке, поэтому после их изменения приложение надо
пересобрать. Настройки почты читаются при запуске — их смена требует только
перезапуска. Полный список — в `.env.example` и `deploy/timeweb.md`.
